# Лекция 4. Lighting and materials

## Повторение: матричные преобразования
- Аффинные преобразования задаются матрицами 4×4: верхний блок 3×3 — линейная часть (поворот, масштаб), последний столбец — перенос.
- Композиция ассоциативна, но **не коммутативна**: A·B ≠ B·A.
  - на слайде: «R·T — объект повернулся по своей оси, затем сдвинулся»; «T·R — сдвинулся, потом повернулся относительно центра, откуда сдвинулся».
  - Осторожно с порядком: при p' = M·p (вектор-столбец, как в GLSL) первой применяется самая правая матрица. Тогда T·R·p — поворот вокруг своей оси, затем сдвиг; R·T·p — сдвиг, затем поворот вокруг начала координат (объект «обходит» центр по дуге). Слайд описывает порядок записи слева направо.
- **Матрица модели** M ставит объект в мир (локальные координаты → мировые): на слайде p' = (S·R·T)·p, P' = M·p. Обычный порядок для p' = M·p — M = T·R·S (сначала масштаб, потом поворот, потом перенос); проверь, что принято в стартовом коде.

## Камера и матрица вида
- Раньше наблюдатель стоял в начале координат и смотрел вдоль +Z. Теперь камеру можно двигать и вращать.
- Камера — это тоже «объект» с позицией и поворотом, т.е. у неё есть своя матрица модели C. Если просто умножить на C, сдвинется сцена, а не наблюдатель.
- **Матрица вида V = C⁻¹** — обратная к матрице модели камеры: сдвигает/поворачивает весь мир так, чтобы камера оказалась в начале координат.
- Обращать произвольную 4×4 не обязательно — обращаем каждую часть отдельно:

```
T⁻¹ = | 1 0 0 -tx |     R⁻¹ = | R³ˣ³ᵀ 0 |     S⁻¹ = | 1/sx  0    0    0 |
      | 0 1 0 -ty |           |   0    1 |           |  0   1/sy  0    0 |
      | 0 0 1 -tz |                                   |  0    0   1/sz  0 |
      | 0 0 0  1  |                                   |  0    0    0    1 |
```
- Поворот ортогонален, поэтому обратная = транспонированная (только блок 3×3).
- **(A·B·C)⁻¹ = C⁻¹·B⁻¹·A⁻¹.** Для камеры C = T·R: V = R⁻¹·T⁻¹ = Rᵀ·T(−pos).

## Всё вместе: MVP
p' = (P · V · M) · p
- M — ставит и ориентирует вершины в мире;
- V — переводит в систему координат камеры;
- P — проецирует 3D → 2D (лекция 1).

## Источники света
Четыре абстрактных типа:
- **Направленный (directional)** — бесконечно удалённый, все лучи параллельны, направление не зависит от положения точки. Пример — Солнце. Параметры: направление, цвет/интенсивность.
- **Точечный (point)** — точка, светит равномерно во все стороны. Параметры: позиция, количество света (цвет), затухание.
- **Прожектор (spot)** — точка, светящая только в конусе вокруг направления; вне конуса темно. Пример — фонарик, уличный фонарь. Параметры: позиция, цвет, направление, угол.
- **Площадной (area)** — светит с поверхности (прямоугольник, диск): окна, вывески. Самый дорогой — нужен интеграл по площади источника.

## Уравнение рендеринга (rendering equation)
L_o(x, ω_o) = L_e(x, ω_o) + ∫_Ω f_r(x, ω_i, ω_o) · L_i(x, ω_i) · cos θ_i dω_i
- L_o(x, ω_o) — излучение из точки x в направлении ω_o (к камере);
- L_e — свет, излучаемый самой поверхностью;
- f_r — **BRDF** материала: как свет из ω_i отражается в ω_o;
- L_i(x, ω_i) — входящее излучение из направления ω_i;
- cos θ_i — учёт угла падения;
- dω_i — элемент телесного угла; Ω — полусфера над поверхностью.

Смысл: каждая видимая точка освещается светом со всех направлений, а материал решает, сколько отразить к камере. Модели ниже — дешёвые приближения этого интеграла для конечного числа источников.

## Модель Блинна–Фонга
L_V(v) = [ ρ_d·(n·l) + ρ_s·(n·h)ⁿ ] · (n·l) · E_L(l)

- L_V(v) — видимый свет вдоль направления наблюдения v;
- E_L(l) — свет (цвет × интенсивность) источника, приходящий по направлению l;
- n — нормаль поверхности; l — направление на источник; v — направление на камеру (все нормированы);
- ρ_d — альбедо (диффузный цвет материала); ρ_s — цвет блика (specular); n (степень) — блеск (shininess);
- **h = (v + l) / |v + l|** — половинный вектор между направлением на камеру и на свет.
- Скобки ⌢ над скалярными произведениями на слайде означают «ограничить снизу нулём»: max(n·l, 0), max(n·h, 0).
- Схема векторов: N — нормаль, L — на свет, V — на глаз, H — между V и L, R — отражённый L.

## Ламбертовый (диффузный) материал
- Закон Ламберта: яркость идеально рассеивающей поверхности одинакова во всех направлениях наблюдения; освещённость зависит только от угла падения.
- d²Q_n = dQ_n · dω · cos φ;  I_φ = I₀ · cos φ (I₀ — сила света плоской поверхности).
- В шейдере: **C = I · cos θ · K_d = I · K_d · (n · ω)**, ω — направление на свет, K_d — диффузный цвет.
- Это дёшево и уже похоже на то, что мы делали (сплошной цвет модели), только с затенением по углу.

## Отражающий материал (блик)
- Добавляется зеркальная составляющая: блик смещается при движении камеры (на слайдах — чайник «diffuse only» vs «diffuse + specular»).
- Фонг: (cos φ)^α, где φ — угол между отражённым лучом r и v.
- **Блинн–Фонг:** C = I · ( cos θ · K_d + K_s · (cos φ)^α ), где h = (ω + v)/|ω + v|, **cos φ = n · h**.
- Свойства материала: K_d (альбедо), K_s (цвет блика), α (блеск).

### Параметр блеска α
Сферы с K_d = красный, K_s = белый: α = 1 → огромное размытое пятно; α = 5 → широкий блик; α = 50 → маленький резкий блик. Чем больше α, тем «глянцевее» поверхность.

## Рассеянный (ambient) свет
- Приближает свет, приходящий отовсюду (переотражения от окружения). Направления нет, поэтому одинаково влияет на все точки.
- Добавка I_a · K_a: без неё неосвещённая сторона объекта чисто чёрная.
- Картинка: итог = ambient + diffuse + specular.

## Затухание: закон обратных квадратов
- Интенсивность падает не линейно, а как **1/D²** (D — расстояние от источника до точки). Коэффициент затухания называют **falloff**.
- Пример: на 2 м свет покрывает площадь в 4 раза больше — 25%; на 3 м — 1/9 (11%); на 4 м — 1/16 (6,25%).
- Применяется к точечным и прожекторным источникам (у направленного затухания нет).

## Итоговая формула
**C = I · ( cos θ · K_d + K_s · (cos φ)^α ) + I_a · K_a**
Материал: K_a, K_d, K_s, α. Для нескольких источников слагаемое в скобках суммируется по всем источникам (каждое со своим I, l и falloff).

## Перенос в шейдер
Что нужно:
- структуры PointLight и SpotLight и передача массивов источников в шейдер;
- расчёт освещения во **фрагментном** шейдере (для каждого пикселя);
- параметры направленного света, ambient, позиция камеры, количество источников;
- параметры материала модели: альбедо, цвет блика, коэффициент блеска.

### Разделение данных по наборам дескрипторов
`set = 0` — общие данные сцены, `set = 1` — данные конкретной модели. Это разделение нужно было уже в лабе 1 для отрисовки множества объектов.
```glsl
layout(std140, set = 0, binding = 0) uniform SceneUniforms {
    mat4 view_projection;
    vec3 camera_position;
    vec3 directional_light_direction;
    vec3 directional_light_color;
    vec3 ambient_light;
    uint point_light_count;
    uint spot_light_count;
} scene_uniforms;

layout(std140, set = 1, binding = 0) uniform ModelUniform {
    mat4 model;
    vec3 albedo;
    vec3 specular;
    float alpha;
} model_uniforms;
```

### Storage buffer для источников
Новый тип ресурса — **storage buffer** (ключевое слово `buffer`). В нём можно объявить массив структур **динамической длины**. Раскладка `std430`, а `set`/`binding` указываются так же, как у uniform-буфера (тип дескриптора на стороне C++ — `VK_DESCRIPTOR_TYPE_STORAGE_BUFFER`, usage буфера — `VK_BUFFER_USAGE_STORAGE_BUFFER_BIT`).
```glsl
struct PointLight {
    vec3 position;
    vec3 color;
};

struct SpotLight {
    vec3 position;
    vec3 color;
    vec3 direction;
    float angle;
};

layout(std430, set = 0, binding = 1) buffer PointLights {
    PointLight point_lights[];
};

layout(std430, set = 0, binding = 2) buffer SpotLights {
    SpotLight spot_lights[];
};
```
Подводный камень (не со слайдов): в std140 и std430 `vec3` выравнивается на 16 байт, поэтому структуры на C++ должны повторять это выравнивание (например, `alignas(16)` или добивать `vec3` до `vec4`/float-паддинга).
